# 早柚核心接入：游戏查询

> 只支持国服。米哈游系的扫码登录走米游社，HoYoLab 国际服没有扫码，不在本方案范围内；鸣潮走库街区，终末地走森空岛。

## 一、它是什么

游戏查询不自己写，交给 [早柚核心 gsuid_core](https://github.com/Genshin-bots/gsuid_core) 加各游戏的插件。装哪些插件、锁哪个版本都写在仓库根目录的 `external.lock.json` 里，一键部署 / 一键更新按它装。

| 游戏 | 插件 | 指令前缀 | 登录 | 许可证 |
|---|---|---|---|---|
| 原神 | [GenshinUID](https://github.com/KimigaiiWuyi/GenshinUID) | `gs` | 米游社扫码（核心自带的「扫码登录」） | GPL-3.0 |
| 崩坏：星穹铁道 | [StarRailUID](https://github.com/baiqwerdvd/StarRailUID) | `sr` | 同上 | GPL-3.0 |
| 绝区零 | [ZZZeroUID](https://github.com/ZZZure/ZZZeroUID) | `zzz`、`绝区零`、`ZZZ` | 同上 | AGPL-3.0 |
| 崩坏3 | [BBBUID](https://github.com/Neroliu/BBBUID) | `bbb`、`崩坏3`、`BBB` | 同上 | 仓库没有许可证文件 |
| 鸣潮 | [XutheringWavesUID](https://github.com/Loping151/XutheringWavesUID) | `ww` | 库街区：私聊发 `ww登录 手机号,验证码`（见第四节） | GPL-3.0 |
| 明日方舟：终末地 | [EndUID](https://github.com/Loping151/EndUID) | `zmd`、`end` | 森空岛扫码：私聊发 `zmd扫码登录`（见第四节） | GPL-3.0 |
| 鸣潮（库街区签到） | [RoverSign](https://github.com/Loping151/RoverSign) | `ww` | 用鸣潮插件的登录 | GPL-3.0 |
| （本仓库）自动签到 | `gscore_plugins/JiangyouyuAuto` | 无指令 | — | GPL-3.0 |

米哈游系四个游戏共用一个米游社登录：扫一次码，四个都能查。鸣潮是库洛的游戏，单独登录库街区；终末地是鹰角的游戏，单独用森空岛 App 扫码。

`gscore_plugins/` 下是本仓库自己写的核心插件，一键部署每次覆盖拷进核心的 `plugins`（不在锁文件里）。

```
QQ ─ SnowLuma ─ 反向 WS ─ NoneBot2（18080）
                            ├─ persona 等原有插件
                            └─ GenshinUID 连接插件 ─ WS ─ 早柚核心（127.0.0.1:8765）
                                                            ├─ GenshinUID（原神）
                                                            ├─ StarRailUID
                                                            ├─ ZZZeroUID
                                                            ├─ BBBUID
                                                            ├─ XutheringWavesUID（鸣潮）
                                                            ├─ RoverSign（鸣潮签到）
                                                            ├─ EndUID（终末地）
                                                            └─ JiangyouyuAuto（本仓库：全员自动签到）
```

- 注意有两个「GenshinUID」：NoneBot 这边的**连接插件** `nonebot-plugin-genshinuid`（`bot.py` 里 `load_plugin("GenshinUID")`），只负责把消息转给核心，各游戏都要它；核心那边的 **GenshinUID 插件**才是原神查询本身。
- 核心是**单独的进程**，不直连 QQ；连接插件把**每一条**消息转给核心，由它判断是不是游戏指令。
- 核心的回复走连接插件发出，**不经过人设插件，不计入群聊限流**。
- 人设插件看到 `GAME_CMD_PREFIXES`（默认 `gs,sr,zzz,bbb,ww,zmd,end,扫码登录,扫码登陆`，见 `persona_rules.DEFAULT_GAME_PREFIXES`）开头的消息不接话、不进上下文和日记。一键部署会给旧的 `persona.env` 自动补上新插件的前缀。
- 核心没开时连接插件跳过（`gscore_link.py`），人设照常，不会变慢。

## 二、安装

**一键部署 / 一键更新会自动装好**核心、`external.lock.json` 里的全部插件和它们各自的依赖，下面是手动做法，排查问题时对照用。

1. 装 [uv](https://docs.astral.sh/uv/)，确认 `uv --version` 能用。
2. 装核心（默认放在仓库的 `gsuid_core\`，已在 `.gitignore` 里；**数据目录里有群友的游戏账号凭据，不要进 git**。装在别处的在 `persona.env` 里设 `GSCORE_DIR`）：

   ```powershell
   git clone https://github.com/Genshin-bots/gsuid_core.git --depth=1 --single-branch
   cd gsuid_core
   uv sync --python 3.12
   ```

3. 装插件（`plugins` 目录核心第一次启动才会建，先手动建好），每个插件 clone 完再装它自己的依赖（核心只在用它的「core安装插件」指令时才自动装依赖，git 拉下来的不会）：

   ```powershell
   mkdir gsuid_core\plugins -Force; cd gsuid_core\plugins
   git clone https://github.com/KimigaiiWuyi/GenshinUID.git --depth=1 --single-branch
   git clone https://github.com/baiqwerdvd/StarRailUID.git --depth=1 --single-branch
   git clone https://github.com/ZZZure/ZZZeroUID.git --depth=1 --single-branch
   git clone https://github.com/Neroliu/BBBUID.git --depth=1 --single-branch
   git clone https://github.com/Loping151/XutheringWavesUID.git --depth=1 --single-branch
   git clone https://github.com/Loping151/EndUID.git --depth=1 --single-branch
   git clone https://github.com/Loping151/RoverSign.git --depth=1 --single-branch
   cd ..\..
   Copy-Item -Recurse -Force ..\gscore_plugins\* gsuid_core\plugins\
   foreach ($p in Get-ChildItem gsuid_core\plugins\*\pyproject.toml) { uv pip install --python .venv\Scripts\python.exe -r $p }
   ```

   `uv sync` 会删掉核心 lock 里没有的包，所以每次 `uv sync` 之后都要重装一遍插件依赖（一键部署就是这个顺序）。
4. 机器人这边装连接插件：已经在 `requirements.lock` 里（`nonebot-plugin-genshinuid`）。
5. `bot\persona.env` 里「早柚核心」那几项照抄样例即可（`GSUID_CORE_REPEAT=true` 让核心重启后自动重连）。
6. 鸣潮和终末地的部分图片用浏览器渲染：核心自带 playwright，第一次启动会在后台自动装 chromium（`GSUID_PLAYWRIGHT_AUTOINSTALL`，默认开），不用手动 `playwright install`。
7. 启动：`.\scripts\启动全部.ps1` 会先起核心再起 NoneBot；不想起核心加 `-NoCore`。首次启动核心会装依赖、下资源，可能超过脚本等待的 90 秒，看 `logs\gscore.out.log` 和 `logs\gscore.err.log`。

## 三、配置（核心网页控制台 `http://127.0.0.1:8765/app`）

注册码在核心目录 `data\config.json` 的 `REGISTER_CODE`。

| 项 | 怎么设 | 为什么 |
|---|---|---|
| 主人账号 `masters` | 填 `DEV_UIN` | 核心的管理指令（`core安装插件`、`core重启`、各插件的「下载全部资源」等）只给主人 |
| 「扫码登陆」服务 | 作用范围改为 `DIRECT` | 二维码只发在私聊（群临时会话），不会被群里别人先扫走；机器人这边另有拦截，见第四节 |
| `core_command` 插件作用范围 | 保持默认 `SV` | 改成 `ALL` 会盖过上面那条服务级的 `DIRECT` |
| `EnableForwardMessage` | 保持「允许」 | 改成拆条发送时，二维码会和文案分开发；机器人这边的群内拦截靠文案认出二维码 |
| 鸣潮「街区登录」「邮箱登录」「抽卡登录」服务 | 作用范围改为 `DIRECT` | 登录链接、手机号和验证码只在私聊出现；机器人这边另有拦截 |
| 终末地「End登录」「End绑定UID」服务 | 作用范围改为 `DIRECT` | 森空岛二维码、cred / token 只在私聊出现；机器人这边另有拦截 |
| 「添加CK」服务 | 保持默认 `DIRECT` | `core添加…` 是粘贴 Cookie，只在私聊收，凭据不会出现在群里 |
| 自动签到 | 不用设 | `JiangyouyuAuto` 启动时自动改好，见第四节「自动签到」；在控制台改回去，下次启动又会被改回来 |
| `WS_TOKEN` / `TRUSTED_IPS` | 保持默认 | 同机只信任 127.0.0.1；核心挪到别的机器时再配 token，并同步 `GSUID_CORE_WS_TOKEN` |

素材：主人在群里发各插件的「下载全部资源」：`gs下载全部资源`、`sr下载全部资源`、`ww下载全部资源`，其它插件按各自 `帮助` 里的资源指令下载。原神素材较大，第一次下载要一阵子。

## 四、群设置与群友用法

1. **群里要允许临时会话**（群设置里打开）。SnowLuma **不能主动发起**临时会话，只能回复对方先发起的（7 天内有效）：没加好友的群友要自己点机器人头像 →「发消息」，在临时会话里操作。
2. 先在群里绑 UID（米游社扫码前必须至少绑一个游戏）：`gs绑定uid 123456789`、`sr绑定uid …`、`zzz绑定uid …`、`bbb绑定uid …`；鸣潮是 `ww绑定 特征码`；终末地不用先绑，直接扫码登录。
3. 群里发「扫码登录」：`bot/plugins/gscore_login.py` 私聊告诉对方怎么做（先试群临时会话，再试好友私聊；没加好友又没发起过临时会话的人收不到），**群里不回任何话**。对方**在私聊里**发「扫码登录」，核心把二维码发在那里，用米游社 App 扫一次，米哈游系游戏共用这一个登录。
   二维码绝不进群，机器人这边有三道保险：群里的登录指令不转给核心（空格、表情隔开也认）；临时会话发不出去也不在群里补话；发往群的消息带二维码文案就拦下，并在之后一分钟里拦掉发往该群的图片。
   **鸣潮**：在私聊里发 `ww登录 手机号,验证码`（验证码在库街区 App 的登录页点「获取验证码」拿，拿到就行，不用在 App 里登录）。群里发 `ww登录` 同样不转给核心，只私聊提醒怎么做；**手机号和验证码千万别发在群里**。只发 `ww登录` 不带参数时插件会回一个网页登录链接，但它指向本机核心（`localhost:8765`），手机打不开，所以统一用短信验证码。登录链接同样被三道保险挡在群外（按链接里的 `/waves/i/` 认）。
   **终末地**：在私聊里发 `zmd扫码登录`，用**森空岛 App** 扫二维码（2 分钟有效）。群里发 `zmd扫码登录` / `zmd登录` 同样不转给核心、只私聊提醒；二维码按「请使用森空岛APP扫码登录」认，挡在群外。
   **凭据指令只在私聊**：`ww添加token`、`ww获取token`、`zmd绑定 cred`、`zmd我的cred`、`zmd查看token` 这类会贴出或显示账号凭据的指令，群里发了也不转给核心，只私聊提醒到私聊里发。
4. 之后在群里直接查，常用指令（以各自的「前缀 + 帮助」为准，比如 `gs帮助`）：

| 游戏 | 抽卡 | 深渊类 | 角色 / 面板 |
|---|---|---|---|
| 原神 | `gs刷新抽卡记录` → `gs抽卡记录` | `gs深渊`、`gs查询幻想真境剧诗`、`gs查询幽境危战` | `gs强制刷新` → `gs查询胡桃` |
| 星铁 | `sr刷新抽卡记录` → `sr抽卡记录` | `sr深渊`（另有虚构叙事、末日幻影等） | `sr强制刷新` → `sr查询希儿`、`sr练度统计` |
| 绝区零 | `zzz刷新抽卡记录` → `zzz抽卡记录` | `zzz深渊`（式舆防卫战） | `zzz刷新面板` → `zzz查询露西`、`zzz练度统计` |
| 崩坏3 | `bbb刷新抽卡记录` → `bbb抽卡记录` | `bbb深渊`、`bbb战场`、`bbb往世乐土` | `bbb刷新面板`、`bbb查询` |
| 鸣潮 | 私聊 `ww导入抽卡链接 链接` → `ww抽卡记录` | `ww深塔`、`ww冥海`、`ww矩阵` | `ww刷新面板` → `ww角色面板`、`ww练度统计` |
| 终末地 | `zmd导入抽卡记录` → `zmd抽卡记录` | `zmd危机合约`、`zmd战争回响` | `zmd刷新面板` → `zmd卡片`；另有 `zmd每日`、`zmd签到`、`zmd基建` |

### 自动签到

**在机器人登录过的账号，每天自动领签到奖励**，不用自己发「开启自动签到」。由本仓库的核心插件 `gscore_plugins/JiangyouyuAuto` 做：

| 游戏 | 签什么 | 时间（默认） | 怎么做到的 |
|---|---|---|---|
| 原神 / 星铁 / 绝区零 / 崩坏3 | 米游社每日签到 | 0:30 左右 | 这几个插件只签订阅了「[游戏] 自动签到」的 UID：每小时（第 7 分）和核心启动时，给每个有米游社 Cookie 的 UID 补上订阅 |
| 鸣潮 | 游戏签到 + 库街区每日任务 | 3:00 | 打开 RoverSign 的「全部开启签到」`SigninMaster`，有库街区登录的都签 |
| 终末地 | 森空岛签到 | 3:00 | 打开 EndUID 的 `SigninMaster` |

- 前提是登录过：米哈游系扫过码（`扫码登录`）、鸣潮 `ww登录`、终末地 `zmd扫码登录`。
- **登录态自动续**，平时不用管：
  - 米哈游系：每天 0:13（签到前）用扫码存下的 Stoken 给每个账号换新 Cookie，等于每人自动发一次 `刷新CK`。只有 Stoken 也失效（改密码、在米游社退出所有设备等）才要重新扫码。
  - 终末地：每次请求用的短期 token 插件自己会从 cred 换；cred 失效时插件只标「无效」，这里每天 2:43 用扫码存下的登录 token 重新换一个。登录 token 也失效才要重新 `zmd扫码登录`。
  - 鸣潮：短期的数据令牌插件自己会续；短信登录拿到的 token 没有续期接口，失效时（插件提示「登录已过期」）要再收一次验证码、私聊 `ww登录 手机号,验证码`。
  - 鸣潮还要注意：库街区同一个账号不让重复登录（RoverSign、作者的 dsh 插件 README 都这么写）。机器人 `ww登录` 后手机上的库街区 App 可能被挤下线；反过来在 App 里重新登录，机器人这边就失效，签到和查询会停，直到再 `ww登录`。天天用库街区 App 的人要知道这一点。
- 启动时还会打开各插件的定时签到 `SchedSignin`，关掉**私聊签到报告**：SnowLuma 主动私聊没加好友的人发不出去，所以静默领取。想看结果的人自己发 `gs签到`、`sr签到`、`ww签到`、`zmd签到` 等，或用各插件的签到状态指令。
- 自己在群里发过 `gs开启自动签到` 的人订阅记在群里，原神插件签完会在那个群发一句「本群共签到成功 N 人」，这是插件原有的行为，补的订阅不会改它。
- 不想要了：把 `gscore_plugins/JiangyouyuAuto` 删掉再跑一键更新，然后在控制台把对应开关改回去。

## 五、迁移

- 原来自写的 `/hsr`、`/zzz` 已下线，`Z:\snowluma\game-data`（角色缓存和 `/hsr 绑定` 的 `bindings.json`）不再使用：群里通知大家在核心里重新绑 UID，确认没问题后把这个目录归档或删掉。
- `persona.env` 里的 `GAME_DATA_TTL`、`GAME_DATA_CHECK_INTERVAL`、`MYS_COOKIE` 可以删掉。

## 六、加一个新游戏插件

1. `external.lock.json` 的 `git` 里照着加一项：`repo`、`commit`、`game`、`prefixes`（人设要避让的拉丁字母前缀，中文前缀别放，免得平常聊这个游戏人设就闭嘴）、`help`（冒烟测试发的帮助指令），插件有自己的登录指令就再加 `login`。
2. `bot/persona_rules.py` 的 `DEFAULT_GAME_PREFIXES`、`persona.env.example` 的 `GAME_CMD_PREFIXES` 加上前缀（`tests/test_persona_rules.py` 会检查有没有漏）。
3. 看插件的登录方式：会往群里发二维码或登录链接的，把登录指令加进 `bot/gscore_guard.py` 的 `PREFIXED_LOGIN`、会贴出或显示凭据的指令加进 `PREFIXED_PRIVATE`、私聊提醒加进 `LOGIN_HINTS`、二维码文案或链接特征加进 `LOGIN_MARKERS`，在 `tests/test_gscore_guard.py` 补用例（冒烟测试会按锁文件的 `login` 和 `LOGIN_MARKERS` 自动查）。
4. 更新本文第一节和第四节的表、README 的功能列表，在 GitHub Actions 里手动跑「依赖自动更新」（勾 `validate_only`、选这个分支）做一遍 Windows 上的完整验证。

## 七、已知问题

- 官方文档提醒：QQ 机器人发二维码图片可能触发腾讯风控。
- SnowLuma 只回复对方先发起的临时会话，机器人没法主动找没加好友的群友；群里发「扫码登录」后没收到私聊，就自己点机器人头像发起临时会话，再发「扫码登录」。群里不会有任何提示。
- 人设按前缀避让，`zzz困死了`、`bbb笑死` 这类聊天人设也会闭嘴（核心也不会回）；前缀后面紧跟它自己的末字母不算指令，所以 `www笑死`、`www.` 开头的链接、`zzzz` 不受影响；终末地的 `end` 前缀会让 `ending`、`end了` 这类英文开头的聊天人设也闭嘴；可在 `GAME_CMD_PREFIXES` 里调整；反过来「绝区零」「崩坏3」开头的指令（如 `绝区零深渊`）不在默认前缀里，人设可能和核心一起回。
- 崩坏3 插件 BBBUID 较新（2026-05 创建、单人维护），没有前两款那种完整面板。
- 鸣潮插件原先的 `tyql688/WutheringWavesUID` 仓库已经没了，现在用的是 Loping151 维护的 XutheringWavesUID。它的网页登录要核心能从外网访问（或另配 `WavesLoginUrl` 外置登录服务），我们没开，只用短信验证码登录。
- 终末地插件 EndUID 也是 Loping151 维护，2026-01 创建。手机号网页登录同样要另配 `EndLoginUrl`，没配时 `zmd登录` 会自动走森空岛扫码。
- 协议见第一节的表；我们只作为独立服务运行，不把它们的代码并进本仓库。
