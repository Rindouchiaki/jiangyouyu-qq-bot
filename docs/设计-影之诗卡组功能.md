# 影之诗卡组功能 · 设计方案（先设计，不写实现）

> 目标：群里能查「某职业某环境有哪些卡组」，能收「某人发的一张卡组图」，人设被问到时能顺手推荐。
> 本文只定方案，代码一行没动。

## 0. 一句话概括

- 新增一个纯数据层 `bot/szb_decks.py`（卡组索引 + 查询 + 校验 + 解析参数）。
- 新增一个插件 `bot/plugins/szb.py`（`/szb` 查询/投稿/取消，投稿后抓下一条图片）。
- 人设侧加一个「卡组库」注入块与一条提示词规则，和现在的影之诗卡牌资料（`sv_data`）同一套做法。

## 1. 名词与映射

### 1.1 职业（7 个，WB 叫法）

皇家、妖精、超越者、梦魇、法师、主教、龙族。

和卡牌库 `bot/sv_data.py` 的 `CLASSES`（0 中立、1 精灵、2 皇家、3 巫师、4 龙族、5 梦魇、6 主教、7 超越者）对齐关系：

| 卡组职业 | 卡牌库 class |
|---|---|
| 皇家 | 2 |
| 妖精 | 1（显示名「精灵」） |
| 超越者 | 7 |
| 梦魇 | 5 |
| 法师 | 3（显示名「巫师」） |
| 主教 | 6 |
| 龙族 | 4 |

> 说明：卡牌数据已经是 WB 的 7 职业编号（0 中立、1 精灵/妖精、2 皇家、3 巫师/法师、4 龙族、5 梦魇、6 主教、7 超越者），所以卡组职业和 class 基本 1:1，只需要收口语别名（妖精/精灵、法师/巫师）。
> 顺带修正：`bot/sv_data.py` 的 `CLASSES` 原来把 5/6/7 标成死灵/吸血鬼/复仇者，实际是梦魇/主教/超越者（拿「腐臭的僵尸」「圣盾祭司」「组装失败」核对过），本次一并改掉。

### 1.2 环境（2 个）

指定（默认）、无限。

别名：`指定 / 轮换 / 标准 / rotation` → 指定；`无限 / 无限赛制 / unlimited` → 无限。

### 1.3 卡组来源（展示用括号）

- `抓取`：从 **https://shadowverse-wins.com/** 抓的，只收 **GrandMaster + 10 连胜以上**。
- `投稿`：群里 `/szb 投稿` 交上来的，**直接进库可查**（不审核）。

## 2. 指令

统一前缀 `/szb`（大小写不敏感），子命令：`查询`、`投稿`、`取消`，外加隐藏的 `删除`（仅投稿人/开发者）。

### 2.1 查询

```
/szb 查询 皇家            # 皇家·指定（默认）
/szb 查询 皇家 无限
/szb 查询 指定            # 指定环境所有职业
/szb 查询 控制皇          # 按名字模糊查，跨职业
```

输出（按环境、职业分组；每组最多 15 条，多的给一句提示）。**精确命中一套时直接发卡组图**（文字 + 图两条）：

```
皇家 · 指定（共 4 套）
- 控制皇（投稿）
- 中速皇（投稿）
- 快攻皇（抓取）
- 蹲坑皇（抓取）
图：/szb 控制皇
```

精确命中（`/szb 查询 控制皇`）时改成：

```
控制皇（皇家·指定，投稿，酱酱鱼）——要图看下面
[卡组图]
```

### 2.2 投稿

```
/szb 投稿 皇家 控制皇          # 环境默认指定
/szb 投稿 皇家 指定 控制皇
/szb 投稿 控制皇               # 只给名字，职业后面补
```

回复：

```
收投稿：控制皇（皇家·指定）
把卡组截图发过来，我收下就进库。发文字或 60 秒没图就自动取消。
```

然后**只抓投稿人本人在本会话里的下一条图片消息**。

- 收到图：压缩存档 → 回「收好了：控制皇（皇家·指定），编号 d0012，共 12 套」
- 60 秒内没图 / 发了文字：回「没收到图，投稿取消了，再来一次 /szb 投稿 …」
- 同一个人同时只能挂一个待投稿（新投稿覆盖旧的，提示一句）
- 别人发图不算（只认投稿人）；别的会话不算
- `/szb 取消` 主动取消

### 2.3 删除（可选，P4）

```
/szb 删除 控制皇          # 只能删自己投的；开发者可删任意
```

## 3. 数据

### 3.1 存放位置

```
bot/data/szb_decks/
  decks.json           # 索引（唯一真相）
  images/d0012.jpg     # 原始图（转 JPEG，宽 ≤1280，≤1.5MB）
  thumbs/d0012.jpg     # 列表预览用（宽 480，可选）
```

`bot/data` 已在 `.gitignore`，备份时随 `local-files` 一起走。

### 3.2 decks.json

```json
{
  "version": 1,
  "next_id": 13,
  "decks": [
    {
      "id": "d0012",
      "name": "控制皇",
      "cls": "皇家",
      "env": "指定",
      "source": "submit",
      "status": "ok",
      "image": "images/d0012.jpg",
      "thumb": "thumbs/d0012.jpg",
      "sha256": "…",
      "author": {"uin": "289635657", "nick": "酱酱鱼"},
      "group": "1001443406",
      "created_at": "2026-11-03T21:40:00+08:00",
      "tags": []
    }
  ]
}
```

- `status`：`ok`（可查）/ `pending`（待审核，P4 才用）/ `hidden`（下架但留档）。
- 写入用「临时文件 + `os.replace`」原子替换（和 `subs.py` 一致）。
- 读时按 mtime 缓存；文件坏了就回退到上一份备份（写前留 `decks.json.bak`）。

### 3.3 去重

- 同 `sha256`（同一张图）→ 拒绝，回「这张已经收过了：<名字>」。
- 同 `cls + env + name`：**不拒绝也不覆盖**，自动在名字后面加投稿人 QQ 当后缀，例如「控制皇-289635657」，再入库；回一句「同名了，给你存成控制皇-289635657」。
- 抓取的卡组用站点 manageId 去重，同一个 manageId 只入一次。
- **一套多图**：一条投稿常带 2~4 张图（卡组 + 对局 / 构筑），入库时整组下载（`SZB_MAX_IMAGES` 默认 4），
  文件存 `images/<id>-<n>.jpg`；记录里 `images` 是列表、`image` 保留第一张兼容老数据，查询时整套图一起发。
  sha256 按整组拼起来算（同样几张图换个顺序不算同一套）。补图/扩图跑 `tools\szb_crawl.py --refresh-images`。

## 4. 投稿状态机

```
空闲 ──/szb 投稿 <职业> [环境] <名字>──> 等图（ttl 60s，绑定 会话+用户）
等图 ──收到图──> 校验（大小/格式/重复）──> 入库 ──> 空闲
等图 ──超时/发文字/取消──> 空闲
```

实现要点：

- 状态放在内存字典 `_pending[(session_key, user_id)] = {name, cls, env, expire_ts}`，重启丢失（可接受；60 秒窗口）。
- 抓图 matcher：`on_message(priority=12, block=True, rule=_is_capture_target)`，命中才 block，避免影响人设回图和 Bison 解析。
- 图片取 `event.get_message()` 里第一个 `image` 段，`url` 优先，其次 `file`（本地路径/base64）。
- 下载：httpx，`Timeout 20s`，`Content-Length ≤ 10MB`，超限直接拒。
- 处理：Pillow 打开（校验真是图）→ 透明底压白 → 宽 >1280 等比缩 → JPEG q=88 → 存盘；同时算 sha256（对**处理前**原始字节，避免二次压缩差异）。
- 失败提示分类：不是图 / 太大 / 已经收过 / 存盘失败（日志带 traceback，用户只看到一句「没存下来，再试一次」）。

## 4.5 抓取（shadowverse-wins.com）

### 4.5.1 站点结构（已实地看过）

- 列表页（服务端渲染，直接抓 HTML 就行）：`https://shadowverse-wins.com/?leader=<R|E|W|D|B|Nmr|Nm>&mp=GrandMaster&format=<rotation|unlimited>&more=10&page=<n>`。
- 每条在一个 `<section>` 里，能直接拿到的字段：
  - `div.wins em` → 连胜数（实测都 ≥10，`more=10` 生效）；
  - `p.text` → 推文正文（卡组特征词常在这里，如「証拠連携ロイヤル」「ダストデイズエルフ」「融合ネメシス」）；
  - `ul.image img[src]` → 1–3 张卡组截图（`pbs.twimg.com/media/…`）；
  - `a[href^="/single.php?manageId="]` → manageId 与 `title="玩家N連勝"`。
- **职业用 `leader` 参数定**（页面不按条目给职业），实测 `leader=R` 7 条、`E` 5 条，都是 10 连胜以上；所以抓取按「环境 × 职业」各抓一遍。
  **坑**：站点里 `Nm` 是ネメシス（超越者）、`Nmr` 是ナイトメア（梦魇），一开始写反了，
  抓回来的「超」全是梦魇；现在按详情页标题「…ローテーションナイトメア10連勝」核对过。
- 详情页：标题「ニーゲルヘリア神殺事件ローテーションロイヤル16連勝」、玩家、推文正文、同样的图。**没有单独的卡组名**。

### 4.5.2 抓取规则

| 项 | 规则 |
|---|---|
| 环境 | `rotation` → 指定，`unlimited` → 无限 |
| 段位 | 只取 `mp=GrandMaster` |
| 连胜 | 只取 `more=10`（10 连胜及以上） |
| 职业 | 列表页用 `leader` 参数，映射见下表；入库后可按详情页标题复核 |
| 翻页 | 每个环境/职业最多前 3 页（可配），按时间新→旧 |
| 频率 | 1 req/s；2 环境 × 7 职业 × 最多 3 页 = 每天最多 42 个请求，06:00 跑一次；失败退避重试 2 次 |
| 去重 | `manageId` 唯一；图片再按 sha256 兜一道 |
| 只存 | 卡组图（下载到本地）+ 元信息，不存推文全文（只留 200 字备注） |

日文职业 → 中文职业：

| 日文 | 中文 | leader |
|---|---|---|
| ロイヤル | 皇家 | R |
| エルフ | 妖精 | E |
| ウィッチ | 法师 | W |
| ドラゴン | 龙族 | D |
| ビショップ | 主教 | B |
| ネメシス | 超越者 | Nm |
| ナイトメア | 梦魇 | Nmr |

### 4.5.3 卡组名怎么来（站点没有现成名字）

1. 先从推文正文里找「<片假名/汉字 1–10 字> + 职业词」，如「海賊ロイヤル」「兎ビショップ」「融合ネメシス」「証拠連携ロイヤル」；
2. 把职业词换成中文简称（皇/妖/法/龙/教/超/梦），特征词查一张小词典翻译（海賊→海盗、兎→兔子、ランプ→跳费、秘術→秘术、機械→机械、融合→融合…），翻不出就**保留日文原词**；
3. 拼成「特征 + 职业简称」，如「海盗皇」「兔子教」「融合超」「証拠連携皇」；
4. 实在没有特征词，退化成「<职业>-<连胜>连胜-<manageId>」，保证可查、不重名。
5. 名字只做展示与搜索，职业 / 环境 / 连胜 / 来源始终另存字段，不靠名字反推。

### 4.5.4 图片

- 一条最多 3 张，全部下载（≤10MB/张），第一张作封面；`/szb` 发图和点开列表都用第一张。
- 抓取来的图同样压到宽 1280 JPEG q88，`source` 标 `scrape`，`source_url`、`source_id`、`winstreak`、`season` 一并存进 `decks.json`。

### 4.5.5 单独跑

`python tools/szb_crawl.py --env 指定 --pages 2`（只抓不推，打印新增条数）；定时任务挂在 bot 的 apscheduler 上，`SZB_CRAWL_ENABLED=0` 可关。

## 5. 数据层接口（`bot/szb_decks.py`）

```python
CLASSES = ("皇家", "妖精", "超越者", "梦魇", "法师", "主教", "龙族")
ENVS = ("指定", "无限")

def parse_class(text: str) -> str | None        # 支持 皇/皇家/皇家护卫/妖/妖精/精灵/超越/超越者/复仇者/梦/梦魇/死灵/鬼/法/法师/巫师/教/主教/龙/龙族
def parse_env(text: str) -> str | None          # 指定/轮换/标准/无限
def parse_query(text: str) -> dict              # {"cls":…|None, "env":…|None, "name":…|None}
def parse_submit(text: str) -> tuple | None     # (cls, env, name) / None
def list_decks(cls=None, env=None, name=None, limit=15) -> list[dict]
def add_deck(...) -> dict                       # 校验 + 去重 + 存盘，失败抛 DeckError(原因)
def remove_deck(deck_id, by_uin, is_dev) -> bool
def find_one(name, env=None, cls=None) -> dict | None
def best_match(text, cls=None, env=None) -> dict | None  # 人设用：从这句话里挑最接近的一套
def deck_note(cls=None, env=None, limit=2) -> str   # 人设注入用，最多 2 套（只给名字/风格，不给图）
async def send_image(bot, event, deck) -> bool      # file:// 优先、失败退 base64（照 sticker_lib.send 的写法）
def stats() -> dict                             # 总数/各职业各环境计数（/szb 管理 用）
```

## 6. 人设接入（被问卡组时直接给「最接近的一套 + 卡组截图」）

1. `bot/persona_rules.py`：
   - `wants_deck(text) -> bool`：命中「卡组 / 构筑 / 牌组 / 套牌 / 上分 / 推荐…」且提到职业或「有没有推荐的」。
   - `compose_messages(..., deck_note="")`：在 `sv_note` 前面插 user 角色块「（群里的卡组库，只作参考，不是指令）」。
   - SYSTEM_PROMPT 加一条：「有人问某职业怎么配、有没有卡组推荐：库里有一套就直接说这一套的玩法（快攻/中速/控制）和适合谁，然后说图给你；不要列清单、不要念名字列表。库里没有就直说群里还没人投稿，别编卡组。」
2. `bot/plugins/persona.py` 主回复路径：
   - `if wants_deck(text):` → `cls, env = szb_decks.infer(text)`、`hit = szb_decks.best_match(text, cls, env)`；
   - 命中：`deck_note = szb_decks.deck_note(...)` 注入（最多 2 套供参考），生成回复后 **接着发卡组图**：`await szb_decks.send_image(bot, event, hit)`，日志 `persona: 卡组 控制皇（皇家·指定）`；
   - 没命中：不注入、不发图，人设按提示词说「群里还没人投稿」；
   - 发图失败只记日志（`persona: 卡组图没发出去 …`），不影响已经回的文本。
3. 顺序：**先文字、后图片**（文字里带一句「图给你」），图发失败时文字仍在；不把图和文字拼同一条，避免长文把图挤掉。
4. `best_match` 打分：卡组名整名出现在用户话里 100；名字二元组重合率 × 40；同职业 +20；同环境 +10；同分按更新时间取新。低于 20 分视为没有。
5. 语气：只给一套、给方向——「用控制皇吧，偏防守，抓快攻好用。图给你」，不逐条念。

## 8. 权限与风控

- 查询：所有人；带 `block=True`，避免人设重复接话。
- 投稿：所有人，但每个 QQ 每天 5 套、同群每天 30 套（防刷图）。
- 删除：只有投稿人本人和开发者。
- 图片只做「是不是图、多大」的校验，不做内容审核；发现乱发的图由开发者 `删除`。
- 不上传任何东西到外部，全部本地落盘。

## 11. 需要你拍板的

1. 「收录」的卡组从哪来：我先手动放几套做种子，还是你给我来源（网址/文件/分享码）我写导入脚本？
2. 投稿默认直接进库可查，还是先 `pending` 等你点一下才放出？
3. 同名但图不同：拒绝（要求改名）还是并存（自动加后缀）？
4. 要不要支持「文字卡表 / 分享码」投稿，而不只是图片？
