# 调研：影之诗 2（Worlds Beyond）能接进来的东西

调研时间 2026-11-06。目标：看影之诗 2 代（Shadowverse: Worlds Beyond，简称 WB / SZB2）有哪些现成数据源和开源项目，能接进我们现在的 `/szb` 卡组库、解析插件和人设链路。

先说结论：

1. **官方有公开 JSON，不用登录**，但只有 `/web/*` 这一套接口（`/api/*` 一律 403）。
2. **卡牌数据能直接拿**（887 张，日文卡名），够做 `/szb2 卡名` 查询。
3. **卡组码（deck code）能读不能写**：本地按格式拆得开，官方校验接口要登录 + csrf，不做「导入到我的卡组」这类功能。
4. 现成的 `/szb` 爬虫（`tools/szb_crawl.py` → `shadowverse-wins.com`）**本来就是 2 代数据**（站点已切 WB，`seasonId=70`，职业代号还是 `Nm`/`Nmr`），所以卡组库这块不用推倒重来。

## 一、数据接口（都实测过）

| 用途 | 端点 | 返回 |
|---|---|---|
| 卡牌库 | `GET https://shadowverse-wb.com/web/CardList/cardList` | `data.count=887`；`data.card_details{card_id:{common:{card_id,name,class,cost,atk,life,skill_text,card_set_id,rarity,deck_enabled_num,card_image_hash,is_token}}}`；另有 `card_set_names` / `tribe_names` / `skill_names` / `stats_list`。每页 20 条，**只有日文卡名**（Referer 换 `/en/`、`/chs/` 或加 `?lang=` 都没用） |
| 卡组详情 | `GET /web/DeckBuilder/deckModal?deck_id=478810&user_id=103895336939&battle_format=2` | `hash`（就是卡组码）、`deck_card_num`、`mana_curve`、`total_red_ether`、`class_id`、随从/法术/护符数量 |
| 卡组广场 | `GET /web/DeckSearch/index` | `count=1000`，`deck_list[{deck_id,user_id,class_id,battle_format,name,view_count,user_name}]`；`page` / `class_id` 参数实测被忽略，得逆向查询串 |
| 卡组码解析 | `GET /web/DeckBuilder/createByDeckHash?hash=<code>` | 未登录 `result_code=10100`，要登录 + `csrf_token` |

卡组码格式（实测样本 `2.2.cdEI.cdEI.cdEI.dmyk…`）：`2.<battle_format>.<每张牌一个 token，按张数重复>`。和 1 代完全不是一回事，没有官方文档。

中文站是有的（`https://shadowverse-wb.com/chs/deck/cardslist/`），但卡名是 JS 渲染，接口里没有中文；想要中文名只能自建映射或人工维护。

第三方站点：

- `https://shadowverse-wins.com/`：已经是 WB 数据，SSR HTML、没有 JSON 接口，详情页只有推文截图、没有卡组码。**我们现有的爬虫可以直接复用**。
- `https://shadowverse.gg/`：英文卡/卡组站，SSR 无 API。
- `https://shadowverse-wb.gamewith.jp/`：日文攻略站。
- `https://shadowverse-portal.com/api/v1/cards?format=json&lang=en`：还能用，但只有 1 代（约 10MB）；`sv.bagoum.com` 已 404，`shadowverse.gamepress.gg` 已下线。

## 三、能接进来的功能（按划算程度排）

1. **`/szb2 卡名` 2 代卡查**（低）
   官方 `cardList` 落盘成 `bot/data/szb2_cards.json`（887 张），按名字/费用/职业查，复用 `/卡` 的排版。纯新增，不动现有 `/szb`，不加新依赖（httpx 已有）。缺点是只有日文名，中文名要另做映射表。

2. **每日环境简报**（中低）
   复用 `tools/szb_crawl.py` 已有数据，按职业、连胜数、时间聚合，每天早上发一条「今天什么职业多、哪套胜率高」。渲染和合并转发都是现成的，几乎只写统计和文案。

3. **卡组码解析 → 卡组图**（中）
   本地按 `2.<format>.<token…>` 拆出 token 列表，用 cardList 补卡名，画一张卡组表。风险在 token ↔ card_id 的映射要自己逆向（官方校验接口要登录）。可以先做「读出来看看是什么」，不做「校验合法性」。

4. **人气卡组榜**（中）
   `DeckSearch/index` 1000 条 + `deckModal` 详情，做「本周最多人抄的 10 套」。要注意限速和缓存，别高频轮询。

5. **截图 OCR 建卡组**（高）
   参考 SVWB-Analyzer 的模板匹配思路，把群友发来的卡组截图直接入库。要加 `onnxruntime` / `rapidocr`，还得知道卡图在哪（卡图 `/uploads/…` 直连 403）。投入产出比目前最差。

6. **对战记录**（高）
   截屏 + 模板匹配记胜负、对手职业。本机 Windows 能做（`tools/ocr_win.ps1` 有经验），但要一直开着游戏窗口，且只能服务一个账号，先放后面。

## 四、风险

- `/api/*` 一律 403；`/web/*` 缺 UA/Referer 也容易 403，**必须限速 + 落盘缓存**，别高频轮询。
- `createByDeckHash` 要登录 + csrf，所以别设计「一键导入到我的卡组」这种需要账号的功能。
- 中文卡名没有接口，界面是 JS 渲染的，只能自建 id → 中文名映射，或者接受日文名。
- 2 代卡牌 ID 是 8 位（如 `10532110`），class 是数字枚举，deck code 前缀 `2.x`，和 1 代不兼容，现有 `LEADERS` 映射要按 2 代重做（`Nm`=超越者、`Nmr`=梦魇 这两条仍然对）。
- License：Apache-2.0 / MIT 可以借鉴；`WBGDB`、`ShadowverseUtility` 没有 License，不能抄代码。
- 卡图 `/uploads/…` 直连 403，卡组图还是继续用投稿截图或自己画。

## 五、建议

先做 **① 2 代卡查**：接口已验证、零登录、零新依赖、群友问得最多，一晚上能上。

再做 **② 每日环境简报**：复用现有爬虫和渲染链路，成本最低，而且比单纯查卡组更有存在感。

`/szb` 现有的卡组库不用改数据源——`shadowverse-wins.com` 已经是 2 代了，只需要在文案和职业表上把「2 代」说清楚。
