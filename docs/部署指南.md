# 部署指南（照着点就行）

> 适用：Windows 10 / 11。全程不用自己开一堆黑窗口敲命令：**双击仓库根目录的 `.cmd`** 就够了。
>
> | 文件 | 干什么 |
> |---|---|
> | `一键部署.cmd` | 装环境、生成配置、然后启动全部。**第一次用**双击它。重复双击没关系，装好的会跳过 |
> | `一键启动.cmd` | 后台启动全部（QQ → SnowLuma → 早柚核心 → 机器人），窗口关掉服务照样跑 |
> | `一键停止.cmd` | 全部停掉（QQ 不关） |
> | `一键更新.cmd` | 拉最新代码、把依赖换到锁定版本、重启。**GitHub 上合并了 PR 以后**双击它 |

---

## 一、准备（只做一次）

1. **装 Git**：<https://git-scm.com/download/win>，一路下一步。
2. **装 QQ NT 桌面版**（官网最新版），装在默认位置 `C:\Program Files\Tencent\QQNT`。装在别处也行，后面在配置里写一下路径。
3. **准备一个大模型 API Key**：默认用 DeepSeek（<https://platform.deepseek.com> → API Keys → 创建）。
4. **准备两个 QQ 号**：机器人用的号（下面叫「机器人号」）和你自己的号（管理指令只认这个）。

Python、uv、SnowLuma、早柚核心、ffmpeg **都不用自己装**，部署脚本会装。

## 二、新电脑：第一次部署

1. 找个放得下几个 G 的地方（比如 `D:\`），在那里右键 →「在终端中打开」，粘贴回车：

   ```powershell
   git clone https://github.com/Rindouchiaki/jiangyouyu-qq-bot.git
   ```

   之后整个机器人都在这个 `jiangyouyu-qq-bot` 文件夹里（下面叫「仓库」）。
2. 打开仓库，**双击 `一键部署.cmd`**。
   - 第一次会问三样：API Key、机器人号、你自己的 QQ 号，粘贴回车。
   - 然后自动下载 Python、依赖、SnowLuma、早柚核心和各游戏插件（原神、星铁、绝区零、崩坏3、鸣潮、终末地），网速一般要 10–20 分钟。
   - 最后会打印 **SnowLuma 网页的初始密码**，记下来（忘了也能在 `bot\persona.env` 的 `SNOWLUMA_WEBUI_PASSWORD` 找到）。
3. 脚本跑完会自动启动。**第一次**还要手动做两件事：
   1. 浏览器打开 <http://127.0.0.1:5099/>，用初始密码登录，按提示改密码、同意协议。
   2. 电脑上的 QQ **登录机器人号**，回到这个网页，确认账号显示「已注入 / 在线」。没注入就点一下 Load。
4. 用你自己的号在群里 @ 机器人说句话，有回复就成了。

**早柚核心（原神 / 星铁 / 绝区零 / 崩坏3 / 鸣潮 / 终末地 查询）**还要在它的网页控制台设一次：<http://127.0.0.1:8765/app>，
注册码在仓库 `gsuid_core\data\config.json` 的 `REGISTER_CODE`。要设的三项（主人账号、「扫码登陆」改 `DIRECT` 等）见
[`早柚核心接入.md`](早柚核心接入.md) 第三节。不需要游戏查询的话可以不管它，人设照常工作。

## 三、旧电脑：从 `Z:\snowluma` 那套换过来

原来那套（`Z:\snowluma\stack\nonebot` + `Z:\snowluma\scripts`）可以直接被新仓库接管，**QQ 登录状态、聊天记录、群友绑定的米游社账号都保留**，什么都不用搬。

1. 拿到最新代码：
   - 已经有仓库：在仓库里右键「在终端中打开」，`git pull`。
   - 还没有：按上面第二节第 1 步 `git clone`，放哪都行（不用放进 `Z:\snowluma`）。
2. **双击 `一键部署.cmd`**。它发现 `Z:\snowluma` 时会问「沿用旧安装？」，回车（= 是）。它会：
   - 拷过来：`persona.env`（你的 API Key、QQ 号、各种设置）、`stack\nonebot\data`（聊天上下文、模式、用量）、`stickers\ori`（表情原图）；
   - **原地继续用**（不拷不搬）：`Z:\snowluma\SnowLuma`、`Z:\snowluma\gsuid_core`、`Z:\snowluma\tools`，写进 `persona.env` 的 `SNOWLUMA_DIR` / `GSCORE_DIR` / `TOOLS_DIR`；
   - 读 SnowLuma 的 `onebot.json`，把连机器人的 token 写进 `persona.env`；
   - 停掉旧脚本起的服务，用新的重新启动。

   旧目录不是 `Z:\snowluma` 的话，在仓库里右键「在终端中打开」：

   ```powershell
   .\scripts\setup.ps1 -From D:\你的旧目录 -Start
   ```
3. **旧日记补标签**（只做一次）：fork#1（记忆按会话隔离）之前机器人写的日记没有「哪个群 / 谁的私聊」标签，自动回忆选不中它们。在仓库里右键「在终端中打开」：

   ```powershell
   .venv\Scripts\python tools\migrate_journal_tags.py
   ```

   先只是**预览**，看一眼要改多少条；没问题再加 `--apply` 真改（会先把原文件备份到白守库旁边的 `<库名>.迁移备份-时间` 文件夹）。
   旧私聊记录分不出是谁，默认不动；只和一个人私聊过的话可以加 `--private-as 那人的QQ号`。其它选项看脚本开头的说明。
4. 确认新的跑得没问题之后，`Z:\snowluma\scripts`、`Z:\snowluma\stack` 就不用了，可以归档。**别删** `Z:\snowluma\SnowLuma`、`gsuid_core`、`tools`，新仓库还在用。

**想退回旧的**：双击 `一键停止.cmd`，再照以前的方式跑 `Z:\snowluma\scripts\启动全部.ps1`。

## 四、日常

- 开机后双击 `一键启动.cmd`。QQ 没开它会帮你开；已经在跑的会跳过。
- 看现在谁在跑：仓库里右键「在终端中打开」，`.\scripts\启动全部.ps1 -Status`。
- 全套自检：`.\scripts\verify-stack.ps1`（全 PASS 或只剩「等待登录」就是好的）。
- 日志在仓库的 `logs\`：`nonebot.out.log`（机器人）、`gscore.out.log`（早柚核心）、`snowluma.out.log`（SnowLuma）。
- 改设置：编辑 `bot\persona.env`（每项上面都有中文说明），改完双击 `一键停止.cmd` 再 `一键启动.cmd`。
  注意一键更新会把回复频率、概率这类调参项换回样例里的新值（账号、密钥、路径不动）；想长期保留自己调过的值，
  在 `bot\` 下新建 `persona.local.env`，只写要改的那几行（格式和 persona.env 一样），它会盖过 persona.env，一键更新不碰。
- 只想临时不开某样：`.\scripts\启动全部.ps1 -NoCore`（不开早柚核心）、`-NoVl`（不开本地视觉模型）、`-NoQQ`（不帮你开 QQ）。

### 掉了会自动补（看护脚本）

`scripts\watchdog.ps1` 每 5 分钟检查一次 NoneBot2(18080) 和本地视觉模型(11435)，发现掉线就调一遍 `start-all-here.ps1` 把它拉回来，过程写进 `logs\watchdog.log`（没掉线时不写）。

- 它只看 `logs\.stack-on` 这个标记：`一键启动.cmd` 起过之后才有标记，所以正常跑的时候它什么都不做、也不刷屏。
- 双击 `一键停止.cmd` 会把标记删掉，看护随之停手，不会把你「停掉」的服务又拉回来。
- 手动跑一次：`.\scripts\watchdog.ps1`。
- 本机已把它注册成计划任务 `JiangyouyuWatchdog`（每 5 分钟一次，当前用户权限、隐藏窗口）：
  `schtasks /Query /TN JiangyouyuWatchdog`
  想关掉看护：`schtasks /Change /TN JiangyouyuWatchdog /DISABLE`；再开：`/ENABLE`。
- 另有一个 `JiangyouyuStack` 计划任务负责「现在就拉起全套」，开机自启的入口是启动文件夹里的 `酱油鱼-启动栈.vbs`（隐藏调 `schtasks /Run /TN JiangyouyuStack`）。
  用计划任务而不是双击窗口跑，是因为从终端/工具窗口起的进程会跟着那个窗口一起被回收，机器人会莫名其妙「没响应」。
- **不闪黑框**：两个计划任务都不直接跑 `powershell.exe`，而是 `wscript.exe` 调 `scripts\run-hidden.vbs`，
  由它用 `WScript.Shell.Run(..., 0, False)` 把 PowerShell 完全藏在后台。所以每 5 分钟的看护巡检、开机自启都不会再闪终端窗口。
  任务本身也设成了 `Hidden`（`Get-ScheduledTask JiangyouyuWatchdog | Select Settings` 可验证）。

## 五、更新

所有外部依赖都锁了版本：Python 包在 `requirements.lock`，SnowLuma、早柚核心和各游戏插件在 `external.lock.json`。
GitHub 上的「依赖自动更新」每天查一次新版本，有新版本就**先在 Windows 云机器上用新版本从零部署、启动整套、跑冒烟测试**，全过了才开一个
`chore(deps): 更新外部依赖（…）` 的 PR，说明里写着变了什么、要留意什么。

1. 在 GitHub 上打开那个 PR，看一眼说明，点 **Merge**。
2. 在跑机器人的电脑上**双击 `一键更新.cmd`**：拉代码 → 停服务 → 装新版本 → 按样例更新 `persona.env` → 重新启动。
   `persona.env` 里的 API Key、QQ 号、外号、token、各种路径和你自己加的项原样保留，回复频率这类调参项换成新版本的默认值，
   窗口里会列出改了哪些、从多少改成多少；旧文件备份成 `bot\persona.env.bak-时间`。不想动它就在终端里跑 `.\scripts\update.ps1 -KeepEnv`。

别的改动（代码、文档）合并以后也是双击 `一键更新.cmd`。

- **想退回**：在 GitHub 上把那个 PR revert 掉（PR 页面底部的 Revert 按钮，再合并生成的 PR），然后双击 `一键更新.cmd`，会按锁文件退回旧版本。
  SnowLuma 升级时替换下来的旧文件还留在 `SnowLuma.bak-旧版本`。
- **第一次要在 GitHub 上开一个开关**（仓库主人做一次）：仓库 Settings → Actions → General → 最下面 Workflow permissions，
  勾上「Allow GitHub Actions to create and approve pull requests」，Save。不勾的话自动更新能查、能测，但开不了 PR。
  fork 出来的仓库还要在 Actions 页面点一下启用工作流。
- 不想等每天的定时：仓库 Actions →「依赖自动更新」→ Run workflow。
- 一键更新会拒绝在仓库有改过的文件时运行（免得覆盖你的改动），按提示处理掉再双击。`bot\persona.env`、`persona.local.env` 这类本机配置不算，不用管。

## 六、常见问题

| 现象 | 怎么办 |
|---|---|
| 双击 `.cmd` 一闪就没 | 在仓库里右键「在终端中打开」，运行 `.\一键部署.cmd`，看最后的红字 |
| 「没找到 git」 | 装 Git 后**重新打开**窗口再双击 |
| 「必填项没填，先不启动」 | 打开 `bot\persona.env`，把 `LLM_API_KEY`、`BOT_UIN` 填上，再双击 `一键部署.cmd` |
| 「SnowLuma 启动失败」 | 看 `logs\snowluma.err.log`；常见是 5099 端口被占，或者杀毒软件拦了 SnowLuma（加白名单） |
| 机器人不回话 | `.\scripts\verify-stack.ps1` 看哪项不是 PASS；「反向 WS 连接」不过多半是 token 不一致，双击 `一键部署.cmd` 会自动对齐 |
| 早柚核心「90 秒内没监听」 | 第一次启动要装依赖、下资源，等几分钟再双击 `一键启动.cmd`；看 `logs\gscore.out.log` |
| 一键更新报 `Failed to read <包>==<版本> ... METADATA: os error 2` | 某个包的上次安装坏了（常见 `rapidfuzz`）。用核心的 venv 重装那个包：`uv pip install --python gsuid_core\.venv\Scripts\python.exe --reinstall-package <包> <包>==<版本>`，再双击 `一键更新.cmd`（实测 12:05 一次 XutheringWavesUID 缘此卡住，修完重跑正常） |
| 终末地怎么登录 | 私聊机器人发 `zmd扫码登录`，用森空岛 App 扫码 |
| 鸣潮怎么登录 | 私聊机器人发 `ww登录 手机号,验证码`，验证码在库街区 App 登录页获取；别发在群里 |
| 群里发「扫码登录」没收到私聊 | 机器人没法主动找没加好友的人：让对方点机器人头像 →「发消息」开临时会话，在那里发「扫码登录」 |
| QQ 不在默认位置 | `bot\persona.env` 里加一行 `QQ_EXE=你的路径\QQ.exe` |
| 白守报 `model 'bge-m3' not found`，向量整理一直失败 | Ollama 桌面版会把模型目录写死到 `C:\Users\<you>\.ollama\models`，而模型其实在 `OLLAMA_MODELS` 指的那份（本机是 `Z:\Ollama\models`）。`scripts\start-all-here.ps1` 已经改成用 `ollama serve` 带着 `OLLAMA_MODELS` 启动（`-NoOllama` 可跳过），重新跑一次 `一键启动.cmd` 就好；确认方式：`curl http://127.0.0.1:11434/api/tags` 里能看到 `bge-m3:latest`，`POST /v1/embeddings` 返回 1024 维 |

更多：架构和端口见 [`架构与运维.md`](架构与运维.md)，早柚核心见 [`早柚核心接入.md`](早柚核心接入.md)。
