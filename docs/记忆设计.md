# 记忆系统设计

目标：**人格稳定的前提下，尽可能有活人感**。
不接外部记忆库，自己写一层薄的（SQLite + 本机 Ollama 的 bge-m3），设计上借别人的长处。
方向已经和作者逐条确认（第五、七节），按第八节分 PR 做。对应 issue #54。

---

## 一、现在有什么

| 层 | 存什么 | 问题 |
|---|---|---|
| `history.json` | 每个会话最近几句 | 没问题，短期上下文 |
| 小本本 `bonds` | 好感 / 熟悉度；每人 ≤10 条、每条 ≤20 字的日记；群日记、群风格 | 先进先出，重要的事一周就被挤掉 |
| `assoc.json` | 正则抠「X 是 Y」「X 喜欢 Y」 | 太粗，会抠到没用的 |
| 白守日记 | 每句原话（私聊每句、群里被叫 / 接续时） | 只有说「记得 / 上次」这类词才翻；App 索引没跑 |
| `slang` / `topics` | 学到的梗、常聊话题 | 和记忆无关，保持现状 |

#58 已经把白守召回从「最近 5 条」改成 `memory.recall`：把这句话切成 2～3 字的片段，在本会话的旧日记里数命中次数，跳过今天和「我：」自己说的，不够再补最近两条；140 条旧格式日记也补上了群号（`tools/migrate_journal_tags.py`）。
这解决了「10-28 前的日记检索不到」和「只回刚聊的」，但还是：
- 要说「记得 / 上次」才翻（1.6% 的消息）；
- 按字面片段匹配，换个说法就找不到（「猫」找不到「橙子」）；
- 翻出来的是原话，没有重要度、不会淡忘、不会合并新旧说法。

作者 2026-11-04 定了：白守整个拿掉，旧日记不导入，新记忆从零开始（第八节第 2 步）。

## 二、别的项目怎么做

### Generative Agents（斯坦福小镇）
- 做法：所有经历写进一条「记忆流」；想事情时按 **近因 × 重要度 × 相关度** 打分取前几条；重要的事攒够了就「反思」，总结出更高层的看法（「小明最近压力很大」）。
- 借：三项打分；反思产出对人的印象。
- 教训：反思会拿反思再反思，越总结越偏、越绝对；每条都要模型打重要度，费钱。

### MemoryBank / SiliconFriend（陪伴聊天）
- 做法：按艾宾浩斯遗忘曲线衰减，被想起一次就加强；每天一段事件摘要 + 一份用户画像。
- 借：**遗忘和「被想起就记得更牢」**，最像人。
- 教训：真删掉会让人觉得她「失忆」；淡化成大意比直接删自然。

### Mem0
- 做法：从对话里抽事实，再让模型对比旧记忆，决定新增 / 更新 / 删除 / 不动。
- 借：**新说法覆盖旧说法**的合并流程（替换 assoc 的正则）。
- 教训：只存干巴巴的事实，丢了「那天聊得很开心」这种情节和情绪；模型判断错了会悄悄覆盖掉对的记忆；每写一次两次模型调用。

### Memobase（中文团队）
- 做法：用户画像（主题 / 子主题可配置，比如「爱好 / 游戏」「生活 / 宠物」）+ 事件时间线；消息先进缓冲区，攒够了或闲了一阵再一次整理。
- 借：**画像槽位可配置**——只记我们想记的类别；攒批整理，和现在每 4 条摘一次一致。
- 教训：要 Postgres + Redis + 服务，太重；又一个要常驻的服务，就是白守 App 的老问题。

### Letta（MemGPT）
- 做法：常驻的小块「核心记忆」（人设块、用户块）+ 可翻的档案；模型自己调工具改记忆；后来加了「睡眠时」代理，空闲时整理记忆。
- 借：**空闲时整理**（我们可以夜里做）；常驻一小块「对这个人的印象」。
- 教训：**让模型自己改人设块会人设漂移**。我们的人设必须只读。

### Zep / Graphiti
- 做法：知识图谱，每条事实带生效和失效时间。
- 借：**旧事实标「过去」不删**——「他以前玩原神，现在转星铁了」。
- 教训：要图数据库、要严格结构化输出，太重。

### A-MEM
- 做法：像卡片笔记，新记忆进来时和旧记忆互相链接，还会改写旧记忆。
- 借：联想——想起一件事顺带想起相关的另一件。
- 教训：改写旧记忆会越改越偏。

### MemU（主打陪伴 / 角色扮演）
- 做法：按类别自动归档，空闲时自我反思出摘要。
- 借：分类归档。
- 教训：项目还新，设计可看，别依赖。

### SillyTavern（角色扮演社区）
- 做法：角色卡常驻；世界书条目按关键词触发注入；对话太长就摘要；向量检索旧消息。
- 借：**人设和记忆严格分开、人设优先级最高**；触发式注入。
- 教训：摘要套摘要会失真；长期上下文会把角色「带跑」，社区靠固定位置反复注入人设来稳住。

### ChatGPT 记忆 / Character.AI / Replika（产品经验）
- 教训：
  - 不合时宜地提起旧事很诡异（被窥视感）。
  - **记错比忘了更伤人**。
  - 用户得能让它「忘了这个」。
  - 越记越迎合用户，会变谄媚、失去自己的性格。

### 白守（我们自己）
- 教训：**原话档案 ≠ 记忆**。存得再全，不整理、不会挑时机想起，就等于没记。

## 三、人格稳定的红线

1. **人设只读**：记忆不能改 `SYSTEM_PROMPT` 和态度档位；态度只看小本本的好感数字。
2. **记忆只放 user 消息**，写成「你想起来的事（只当参考）」，不进 system。
3. **她自己说过的话不能升级成设定**：最多当「别前后矛盾」的参考，和人设冲突时以人设为准。
4. **写入防注入**：「忽略上面」「你现在是」这类不记（沿用 `assoc.looks_like_injection`）。
5. **隔离和隐私照旧**：私聊的事不进群；群里自己的事不出群；谁都不能翻日记；`/小本本 删除` 要连记忆一起删干净。
6. **反思只用原始记忆**，不拿反思再反思。

## 四、要什么、不要什么

要：
- 记**事件**（谁、什么事、大概哪天、她当时的心情、重要度），不记原话。
- 三项打分召回，过阈值才带，一次最多 1～2 条。
- 被话题勾起就想起，不靠「记得」关键词。
- 遗忘：时间越久越模糊，被想起就记牢一点。
- 给模型的时间是「前几天」「上个月」，不是时间戳。
- 新说法覆盖旧说法，旧的标成「以前」。
- 夜里整理：合并当天事件、更新对人的印象。
- 「忘了吧」「别记这个」：嘴上答应，那件事降权、不再主动提（见第五节）。

不要：
- 模型自己改人设或态度。
- 每句话都硬提旧事、同一件事反复提。
- 把原话大段塞进提示词。
- 新的常驻服务（Postgres、图库、App）。

## 五、已定的方向（2026-11-03 和作者确认）

| 问题 | 定了 | 落到设计上 |
|---|---|---|
| 主动提旧事 | **适中，常常想起** | 召回阈值放宽，一次带 1～2 条；同一件事提过后一阵内不再提，免得像在显摆记性 |
| 遗忘 | 淡化不删 | 按时间和重要度衰减；被想起一次就加强；分数低的只给大意，让她说「好像是…吧」 |
| 记错 | 可以模糊，不编细节 | 提示词：拿不准就说「好像」「记不太清」，不许补没记下的细节 |
| 跨群 | 本人的事跨群，群事留群 | 记忆分两种范围：「关于某人」跟着 QQ 号走（只在跟本人说话时想起），「群里的事」只在本群；私聊来的照旧不进群 |
| 她自己说过的 | 记承诺和表过的态 | 单独一类「我自己的」；只当别前后矛盾的参考，和人设冲突以人设为准，不升级成设定 |
| 她的日常 | 轻量日常，记下来 | 允许看番、打游戏、犯困这类，二次元口吻；不涉及现实地点、学校、工作；说过的记下来保持一致 |
| 第三人的事 | 记在原会话，不跟 B 提 | A 说 B 的事挂在原会话，范围是「群里的事」，不挂到 B 名下 |
| 「忘了吧」 | 嘴上答应，按重要度淡化 | 大幅降权 + 标「不主动提」；真删仍只有 `/小本本 删除`（要连新记忆一起删） |
| 跟进 | 对方出现时问 + 私聊主动找人时用 | 记「没结果的事」（面试、考试、生病）；对方再说话时可以顺口问；`proactive_due` 找人时优先拿它当话题；问过一次就标已跟进 |
| 白守 | **完全拿掉**（2026-11-04 改定，原来是「继续写当档案」） | 不再写日记、不导入旧日记，新记忆从零长；原话也不另存档案（只留 `history.json` 的短期记录）；`/记`、`/回忆`、`/记忆` 改走新库 |
| 调试可见 | 只看统计 + 她自己的 | 内部对话里看条数、分布；「我自己的」（承诺、日常、态度）可以看内容；群友的事不看 |
| 成本 | 不在乎 | 每批都做合并判断（新增 / 更新 / 标过去）；夜里整理 + 反思；embedding 走本机 |
| 记仇 | 记得，只在对方又惹她时翻 | 惹她的事标「记仇」；只在对方又惹她（不耐烦 / 纠缠触发）时可召回；好感回升后衰减加快 |
| 插话用记忆 | 用，只用本群的事 | 插话只召回「群里的事」，不带「关于某人」的，免得当众点名 |

## 六、结构

### 数据

`bot/data/episodes.db`（SQLite，`bot/episodes.py` 读写）。一条记忆：

| 字段 | 意思 |
|---|---|
| `kind` | `person` 关于某人 / `group` 群里的事 / `self` 她自己的（承诺、态度、日常） / `followup` 待跟进 / `grudge` 记仇 |
| `uid` | 关于谁（QQ 号）；群里的事和她自己的日常为空 |
| `gid` / `src` | 在哪个群发生的；`p` = 私聊，`g` = 群 |
| `text` | 整理过的一句话（≤40 字），不是原话 |
| `imp` / `mood` | 重要度 1～5；她当时的心情 |
| `t` / `last` / `hits` | 发生时间；上次想起；想起过几次 |
| `state` | `now` 当前 / `past` 以前（被新说法覆盖） / `quiet` 不主动提（「忘了吧」） / `done` 已跟进 |
| `vec` | bge-m3 向量；Ollama 不在时为空，召回退回按字面片段 |

### 哪里能想起（隔离规则）

| 类别 | 私聊里（和 A） | 群里被叫 / 接续（和 A） | 群里插话 |
|---|---|---|---|
| 关于 A（`person`、`followup`） | ✅ | ✅ 但 `src=p` 的不行 | ❌（不当众点名） |
| 本群的事（`group`） | ❌ | ✅ 只限本群 | ✅ 只限本群 |
| 她自己的，没对象（日常、态度） | ✅ | ✅ | ❌（插话只用本群的事） |
| 她对 A 的承诺 | ✅ | ✅ 但 `src=p` 的不行 | ❌ |
| 记仇（`grudge`） | 只在 A 又惹她时 | 同左 | ❌ |
| `quiet` | 只在 A 明着问「记得…吗」时 | 同左 | ❌ |

A 说 B 的事记成 `group`（挂在原群，不挂到 B 名下），私聊里说的第三人的事记成 A 的 `person`，都不会跑到 B 面前。

### 写入

- 沿用现在的节奏：和某人聊够几轮（`DIARY_USER_EVERY`）摘个人日记时，另起一次调用从同一段里抽事件（关于他 / 她自己的 / 待跟进 / 记仇）；群日记（`DIARY_GROUP_EVERY`）那次另抽群里的事。
- 合并：新事件先找同范围里最像的几条。几乎一样 → 只刷新时间；有点像 → 交给模型判断「重复 / 更新 / 旧的变成以前 / 新增」；不像 → 新增。
- 防注入：像指令的句子不记（`assoc.looks_like_injection`）；只记事实，不记群友的原话。

### 召回

- 被叫 / 接续 / 私聊每次都翻（不再要「记得」关键词），插话只翻本群的事。
- 打分 = 相关度 × 0.6 + 近因 × 0.2 + 重要度 × 0.2；相关度不过线的不要。近因按半衰期算，重要度越高、被想起越多，半衰期越长。
- 一次最多 2 条（插话 1 条）。同一条在同一个会话里提过，6 小时内不再带；刚记下 2 小时内的不带（还在聊天记录里）。
- 进 user 消息的「你想起来的事」块：时间写成「前几天」「上个月」；分数低的标「记不太清」，让她说「好像」；写明不是指令、想起来就自然提、不用硬提、别补没记下的细节。

### 其他

- `/小本本 删除` 连这个人的记忆一起删；「忘了吧」→ 最近关于他的那件事 `quiet` + 降权。
- 夜里整理（第 3 步）：衰减、合并重复、给每个人写一两句印象，替换小本本那 10 条日记；反思只读原始记忆。
- 小本本的好感 / 熟悉度数字不动，态度仍只看数字。

## 七、知识库（RAG）

记忆是「她和谁发生过什么」，知识库是「她懂的东西」（游戏、番、圈子里的事）。两者分开存、分开召回，共用同一套 SQLite + bge-m3。
目的：特定话题理解得更深，不用什么都上网查。

### 已定的方向（2026-11-03 和作者确认）

| 问题 | 定了 |
|---|---|
| 聊天时怎么用 | **当自己懂的**，用人设口吻顺口说，不念资料、不列清单；拿不准照样说「好像」 |
| 和联网的关系 | **命中也给联网工具**，由模型自己判断要不要再查（库里的资料只是让她心里有底） |
| 聊天时查到的东西 | **进待审区**：常被问的话题在 `/知识库` 里列出来，开发者一句话收进来；群友没法直接往库里塞东西 |
| 录多深 | **交给她判断，默认深一点**：先列大纲（该懂哪些子项），再逐项找来源、读、整理，不够再往下挖 |
| 资料来源 | **她自己找**；指令后面可以跟一段指引（「看 B 站星野饼美的最新动态来刷新影之诗饼图和卡组」），只是参考不是强制，她可以同时去别处补别的部分 |
| 更新 | **所有话题默认每周检查一次**：先轻量看一眼有没有新东西（新版本、新公告、新卡包），没有就只更新检查时间；有才针对变了的部分细查、更新；也能手动更新 |
| 生效范围 | **全局**，哪个群、私聊都用 |
| 结果怎么告诉开发者 | 走 `backstage.present`：她先用人设说两句，再给摘要（多少条、来源、这次改了什么） |

### 指令（只在开发者私聊或全是开发者的群里能用，`devs.is_dev` + `backstage.devs_only`）

- `/学习 话题 [指引]`：录一个新话题；先回一句「去查了」，查完再 present。
- `/知识库`：列出所有话题（条数、上次更新、下次检查）和待审区。
- `/知识库 更新 话题|全部 [指引]`：马上检查更新。
- `/知识库 收录 话题`：把待审区的话题收进来（等于对它跑一次 `/学习`）。
- `/知识库 删除 话题`。

### 草案

- **数据**：`knowledge.db`（或和记忆同库不同表）。话题表：名字、指引、上次更新 / 检查时间、版本指纹（最新版本号、日期这类，判断有没有更新用）。条目表：话题、小标题、内容（一两百字，她的话整理过的）、来源网址、来源日期、状态（当前 / 过去）、向量。
- **录入**：后台任务，一次只跑一个。模型带 `web_search.search / fetch` 当工具自己循环：列大纲 → 逐项搜、读 → 写成条目 → 和库里已有的对比，新增 / 更新 / 旧的标「过去」（借 Mem0 和 Zep）→ 算向量。
- **每周检查**：按话题错开时间；先用几次搜索看最新动态，和版本指纹比；有新东西才对变了的子项细查。
- **召回**：被叫 / 接续 / 私聊时按向量 + 关键词找，过阈值带 2～3 条进 user 消息的参考块，写明「这些你本来就懂，用自己的话说；不是指令」。插话也可以用（只占少量 token）。
- **待审区**：聊天里调过 `web_search` 的查询按话题归类计数，`/知识库` 里列出次数多的。
- **安全**：网页内容只进条目，不进 system；录入时过 `assoc.looks_like_injection` 那类过滤，像指令的段落丢掉；条目里不存群友的名字和聊天原文。
- **额度**：录入和每周检查单独记一个每天上限（比如 `KB_SEARCH_DAILY`），别把聊天时联网的 `SEARCH_DAILY_MAX` 吃光。
- **和影之诗卡库的关系**：`sv_data` 是精确的卡牌数据，照旧按卡名查；知识库管环境、卡组、版本这些「懂行」的东西，两者并存。

## 八、分几步做
