# 图片 / 表情包识别：最小 token 方案评估

> 结论先说：**图片理解全部放本地，模型只收一张 ≤60 字的「图卡」**。默认档（T1）API 花费 0 元，每次最多多 10–40 token（约占当前单轮输入的 2%–7%），且只在「需要理解这张图」的时候才做。

---

## 1. 现状

| 项 | 现状 |
| --- | --- |
| 图片消息 | `persona.py:508-510` 用 `event.get_plaintext()` 取文本，纯图片消息文本为空 → **直接 return，机器人完全看不见图** |
| 表情包发送 | 已本地化：`sticker_lib.pick_for_mood(mood, key)` 按「情绪标签 + 类别」选图，**0 token** |
| 表情包索引 | `Z:\snowluma\stickers\index.json`：513 条，141 条带 OCR 文字，平均文字 10.6 字；类别分布：无文字 372 / 其他 113 / 疑问 12 / 生气 5 / 卖萌 4 / 回应 3 / 搞笑 2 / 夸奖 1 / 拒绝 1 |
| token 实测 | `data/usage.jsonl` 37 次调用：平均输入 **607.6**、输出 **5.6**、缓存命中 30.2% |
| 机器 | Ryzen 5 3600X / 16GB / RTX 3060 Ti（8GB 显存）；无 Ollama、无 Tesseract |

所以「加图片识别」不是优化现有链路，而是**从 0 到 1 补一条本地感知链路**。

| 档 | 做法 | 每张图 token | 延迟 | 成本 | 能看懂什么 |
| --- | --- | --- | --- | --- | --- |

**推荐 T1，T2 作为可选增值，T3/T4 只在手动 `/看图` 时按需触发。**

## 3. 已实测的关键事实

### 3.1 Windows 自带 OCR 可用（零安装、零联网）

- 系统 OCR 语言：`en-US`、`zh-Hans-CN` 均可（`OcrEngine.AvailableRecognizerLanguages`）。
- 封装脚本：`Z:\snowluma\tools\ocr_win.ps1`（`Windows.Media.Ocr`，PowerShell 5.1；**必须用 `powershell.exe`，pwsh 7 的 WinRT 互操作不支持**；脚本需带 BOM 存盘，否则 5.1 解析报错）。
- 8 张有字表情包实测：**平均 423.8 ms/张**（含 PowerShell 启动 ~250ms），最长 488ms。

样例（识别 → 清理后）：

| 图 | 耗时 | 识别文字 |
| --- | --- | --- |
| 73d2ee09 | 488ms | 脑罕里有答案“·那不相当于在弊吗。敢不敢堂堂亠比一运气@咿呀（有噪声） |
| 1999d7b3 | 436ms | 等着进局子吧你 |
| 4127995f | 418ms | 生活苦涩 |
| 93494838 | 402ms | 一个未成年的孩子不解的注视着 |

结论：**大字清晰图识别可用，小字/花字/艺术字会出噪声**，所以图卡必须做清洗（去空格、只留 CJK/字母数字、短行丢弃、去重）并截断。

### 3.2 表情包靠哈希识别，不必过模型

收到图 → 下载 → `sha1` 命中 `stickers/index.json` 的 513 条 → 直接拿到 `category` 和 `text`。
重压缩过的同图用 `dhash`（64bit，汉明距离 ≤6）兜底。命中时图卡只有 `[表情:卖萌]` 或 `[表情:字“生活苦涩”]`，**5–12 token**。

## 4. 推荐架构（T1）

```
图片段
 ├─ 下载（httpx，≤5MB，3s 超时；复用 OneBot 的 url/file）
 ├─ ① sha1 命中表情库？ → 图卡 = "[表情:卖萌]" / "[表情:字“…”]"        （5–12 token）
 │     否则 dhash 近邻 ≤6 → 同上
 ├─ ② 未命中 → Windows OCR（~0.42s）
 │     文字 ≥4 字 → "[图片:…]"（清洗后截 60 字）                        （≈30–40 token）
 │     文字 <4 字 → 启发式：宽高比/是否截图 → "[图片:截图]" / "[图片]"    （3–8 token）
 └─ 结果按 sha1 缓存，同一张图只算一次
```

**注入时机（省 token 的关键）**——只在这几种情况把图卡拼进消息文本：

1. 被 @ / 私聊（本来就要回）；
2. 正在接续的话题里（engaged）；
3. 这条消息是对机器人消息的引用/回复；
4. 对方明确在问图（「这图啥意思」「你看这个」）。

普通群友发图没人提 → 不 OCR、不注入、0 token。

**接线点**：`persona.py:508` 的 `if not text: return` 改成「文本为空且带图片且满足注入时机 → 用图卡代替文本」，图卡以 `[图片]…` 前缀进入 `compose_messages`，历史里同样按该形式存。

## 5. token 记账

按 DeepSeek 中文约 0.5–0.7 token/字估算：

| 场景 | 图卡长度 | token | 每天 200 张图的增量 |
| --- | --- | --- | --- |
| 表情库命中 | 6–12 字 | 5–12 | ≈ 1.2k–2.4k |
| OCR 图卡 | ≤60 字 | 30–42 | ≈ 6k–8.4k |
| 无字图 | 2–6 字 | 3–8 | ≈ 0.6k–1.6k |

对照当前 607 token/轮：单次最多 +7%；**按输入价 ¥2/百万 token 计，200 张/天约 ¥0.01–0.02/月**，可忽略。相比之下云端 VLM 每张 800–1500 token，成本高 20–40 倍。

## 7. 可选 T2（本地视觉模型）

- Ollama + `qwen2.5vl:3b`（约 3.2GB，RTX 3060 Ti 8GB 可跑）。
- 只在「无文字照片 + 用户问图」时调用，单张 2–6s；输出压成 20 字描述再入上下文（≈20 token）。
- 不装也能用 T1；装了也只是「按需」调用，不改变平均成本。

## 8. 风险与边界

1. **OCR 噪声**：艺术字、竖排、小字会出错误字；对策是清洗 + 截断 + 图卡前缀明确标注「机器识读」，避免模型把噪声当事实。
2. **PowerShell 启动开销**：每张 0.25s 左右；命中表情库时完全不调 OCR。
3. **隐私**：全程本机，不出网（下载图片本身除外）。
4. **图片尺寸**：QQ 图片通常有 CDN 原图，注意 5MB 上限与 3s 超时，失败只记 `[图片]`。
5. **雪崩**：群聊刷图时只在注入时机触发 OCR，并加每群每 10s 最多 3 次的限流。
